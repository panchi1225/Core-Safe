# 発行済み新規入場者QRへの会社マスター反映

会社マスターの保存後、各有効QRの `contractorOptions` を最新の会社名に同期する。token・URL・現場・作業所長・有効期限は変更しないため、印刷済みの期限内token QRを継続使用できる。匿名の読取りは従来どおり有効tokenの設定1件のみで、`masterData` 全体や社員情報の取得権限は追加しない。

- マスターで会社を追加すると、保存完了後に既存の各現場QRでも選択可能。
- 会社名の変更・削除も会社候補に反映。既に提出済みの回答の会社名は変更しない。
- QR発行画面を開いたままマスターが更新された場合も、発行時に最新マスターをトランザクションで再取得する。

同期は100件ずつページ取得し、各ページのトランザクション内でマスターとQRを再確認する。同時更新はFirestoreの競合再試行に任せ、古い同期処理による上書きを防ぐ。無効・期限切れQRを有効に戻さない。同じ会社一覧には再書込みしない。既存マスターの会社名に前後空白や重複がある場合は、同期時に会社名フィールドのみ整理する。会社名は200文字、候補は300件の既存公開QR上限を保存前に確認する。

マスター保存と複数ページの同期は一括の原子操作ではない。途中で権限・通信エラーが起きると、会社マスターは保存済みでも一部QRが未反映になる。その場合は「会社マスターは保存しましたが…」と表示し、再保存またはQR管理画面を開き直すことで再同期する。端末のキャッシュではなくサーバーから設定を取得するため、再度QRを読んだ際には反映済みの選択肢が表示される。既に開いているアンケートをリアルタイム更新する機能ではない。

## 反映手順

1. 更新した `firestore.rules` を対象Firebaseへ反映する。社員のみ `contractorOptions` を変更でき、変更後の一覧が `getAfter(masterData/general).contractors` と一致する場合に限定する。他の公開設定変更制限・匿名のマスター読取禁止は維持。
2. テスト済みソースをGitHub Pagesに反映する。
3. 社員画面の「新規入場者QRの発行・管理」を一度開く。発行済みの有効QRを現在のマスターへ同期する。新QR発行・再印刷は不要。
4. 会社マスターへ会社を1件追加して保存し、既に印刷したQRを読み直して選択肢・提出を確認する。以後の会社マスター保存は自動同期される。

この変更の作業中に本番Rules・Pages・業務データは変更していない。

## 手入力した会社名について

現行の公開アンケートの「その他（手入力）」は `publicNewcomerSubmissions` の回答に保存される。会社マスターへの自動登録処理は現行ソースに存在せず、この変更では追加しない。匿名から会社マスターへの書込み権限も追加しない。手入力の会社を会社マスターへ登録した後は、今回の同期により既存の各QRに表示される。

公開回答の会社名を無条件にマスターへ採用するか、社員確認後に採用するかは別途決める必要がある。誤入力の自動拡散を避けるため、送信だけでマスターを変更する仕様を暗黙には追加しない。
