# Windows Chrome 実機確認記録

2026-10-08に利用者から受領した確認結果。確認対象はPR #34、`integration/access-control-bulk-pdf`、`7f06e65b229c608c36d60551c70de059ee6ed858`。Windows PCのChrome、`demo-core-safe`のAuthentication / Firestore / Functions Emulator、架空データだけを使用した。本番Firebaseには接続していない。以下は**人間による実機確認**であり、Codexのスタブ検証や画面表示だけから推定した結果ではない。

## 確認できた範囲

1. 社員ログインに成功し、ホームに「帳票一括ダウンロード」が表示された。
2. 検証現場・2026-10-07・4帳票種別で、日誌1件、旧draftsと公開回答のアンケート2件、安全訓練1件、災害防止協議会1件、合計5件を確認した。
3. 実際のWindowsの`showDirectoryPicker`が表示され、選択したWindowsフォルダに5PDFが保存された。現場名 → 帳票種別 → PDFの階層を確認した。
4. PDF実ファイルを開いて正常表示を確認した。旧draftsと公開QR提出のアンケートは同じ帳票レイアウトで、署名、会社名、現場名、作業所長等が正常表示された。
5. 同じ保存先へ再実行し、既存PDFを上書きせず、連番付きで保存された。
6. ZIPのダウンロードに成功し、Windowsで実際に展開して4帳票種別・合計5PDFを確認した。
7. ログインなしで公開QRを開き、架空社員「検証 社員」を選択、生年月日`19950101`によるFunctions照合と社員情報の自動入力に成功した。
8. 署名・アンケート入力・公開送信に成功した。社員画面へ戻るとアンケート3件、全帳票合計6件となり、追加提出が一括PDF対象へ反映された。

公開QR → Functionsによる生年月日照合 → `publicNewcomerSubmissions`保存 → 社員側統合一覧 → 一括PDF対象、という一連の動作を実機確認した。生年月日照合は簡易確認で、社員ログインのAuthenticationとは別である。

## 確定した配色

一括ダウンロードカードのアクセント・枠線・アイコンは`#D4A017`、淡色背景は`#FFF4CC`、ホバーは`#FFE7A3`。利用者が他カードと識別できることを確認し、この配色で確定した。他カードの色は変更していない。今回の最終候補整理ではソースや配色を変更しない。

## この確認に含まれないもの

- 本番Firebase、Authentication、Firestore Rules、Functions、Secret Manager、IAM、App Checkの設定・動作。
- 本番環境の実スマートフォン、iOS Safari、Android Chrome、Edgeでの全機能。
- 実運用データの大量件数、実ディスク容量不足時のOS挙動、本番権限取消中の実バッチ。
- 既存4帳票の全入力・編集・保存操作と従来の印刷ダイアログを網羅した実機回帰確認。

画像PDFの文字選択・検索不可とブラウザ印刷PDFとの完全一致を保証しない仕様は維持する。件数確認時の帳票本文転送も残る。大量件数・エラー停止等の自動テスト成功を、上記の本番・実OS検証の成功として扱わない。
